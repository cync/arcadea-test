topic: Independent law firms struggling with document workflow
goal: Build a solution addressing: (1) documents scattered across email/shared drives/paper making current-version-finding its own task, (2) no visibility into filing status (drafted/reviewed/sent) when attorney is in court, causing silent deadline slippage, (3) JTBD: when a case document moves from draft to filed/sent, want one place showing current version, approval status, and deadline, so nothing is missed and the wrong version is never sent
mode: facilitator
status: complete
updated: 2026-08-04T15:58
---

- (technique) started Starbursting
- (idea) Paralegal is the person who touches the document and/or feels the pain first when a version goes missing or deadline slips
- (idea) Office manager holds backup authority to approve/send when attorney is unreachable
- (idea) Client is an external party who needs visibility into filing status too
- (idea) The main attorney of record is the fixed, single accountable owner of each document, regardless of who last touched it
- (idea) Version tracking granularity: only the last saved version matters, not every save/redline pass
- (idea) Status field needs more granularity: 'reviewed' should show by whom, plus states like 'needs revision' and 'waiting on client signature'
- (idea) 'Wrong version sent' means: an outdated draft filed to court, or an unsigned copy filed to court
- (idea) Scope for 'one place' is intentionally narrow: status + deadline, not sign-off checklists or court filing rules
- (idea) Solution form factor: standalone web application with workflow visualization
- (idea) App does not store files itself — it organizes/indexes files that live in a connected cloud account (e.g. Google Drive)
- (idea) Paper documents get scanned in by a tracked person, and flagged as 'scanned document' with a timestamp + who scanned it
- (idea) Web app is responsive and works from mobile, so attorney can check/update from courthouse
- (idea) A document enters the system from the moment it's created, not only once a deadline is assigned
- (idea) Visualize the 'aging' of each item in the workflow, and send an email warning if an item is untouched for more than 3 days
- (idea) Deadlines are set manually by the main attorney, per case
- (idea) Root cause email/shared-drive fails: people don't follow up on emails, so deadlines get silently lost
- (idea) Independent firms feel this more because of smaller teams and low budget for a proper/advanced document management (GED) system
- (idea) Primary stake of a missed deadline: financial loss to the business
- (idea) Cloud storage connection could use an MCP driver (Claude plugin) rather than a custom-built integration
- (idea) Status changes happen manually via a frontend UI where users move items and collaborate (not inferred automatically)
- (idea) Clients get access to the same frontend, scoped by RBAC so they only see what they have permission to see
- (idea) Office manager gets a delegated approval action in the app to approve/send when the attorney is unreachable
- (insight) Synthesis: core insight is that the product's real job is degrading gracefully when the primary document owner (attorney) goes dark -- aging/3-day-alert and delegated approval are the same insight wearing two hats. The 'don't store files, index the cloud drive' + RBAC client access decision solves the budget/trust problem (no migration, no separate portal). Chosen direction: proceed to PRD with MVP scope = status+deadline tracking, cloud-drive indexing (MCP), Kanban-style collaborative frontend, RBAC, aging visualization + 3-day stale alert, delegated approval action, paper-doc scan tracking.
