- (decision) Seeded from brainstorm-intent.md (2026-08-04 session): problem = independent law firms lack proper GED, docs scattered across email/drive/paper, no visibility when attorney unreachable, silent missed deadlines cause financial loss. JTBD: one place showing version/status/deadline for a case doc moving draft->filed/sent. Central insight: product must degrade gracefully when the primary owner (attorney) is unreachable -- aging alerts + delegated approval are the same insight from two angles.
- (decision) Personas from intent doc: main attorney (fixed doc owner, sets deadlines), paralegal (day-to-day, feels pain first), office manager (backup/delegated approver), client (external, RBAC-scoped viewer).
- (decision) MVP scope IN (from intent doc): status+deadline as source of truth; cloud-drive indexing not file storage (possibly via MCP driver); collaborative Kanban-style frontend, manual status moves; RBAC client access; aging visualization + 3-day stale email alert; delegated approval action for office manager; paper doc scan tracking (timestamp+who); doc enters system at creation; responsive/mobile web app; status granularity (reviewed-by-whom, needs revision, waiting on signature); version = last-saved only. OUT: sign-off checklists, court filing rules/compliance logic -- deliberately narrow to status+deadline, not full case management.
- (decision) Stakes calibration: internal tool for one firm (not a multi-tenant product to launch/sell) -- calibrates rigor/depth toward internal-tool scale (~5-8 pages), single-tenant assumptions, no billing/monetization concerns.
- (decision) Success metrics defined: (1) Activation - % of new matters with >=1 doc uploaded within 24hrs of matter creation, target 80%. (2) Engagement - weekly active documents-in-workflow (moved status >=1x/week) as proxy for real usage vs bypass. (3) Outcome - missed-deadline rate (% deadlined docs not Filed/Sent by due date), target <2%, measured against each firm's self-reported baseline. Counter-signal: if activation is low, hypothesis is onboarding friction, not workflow rejection -- response is to investigate a bulk-import tool from existing drive folders before assuming the core workflow is wrong.
- (decision) Scale: single firm, ~12 people total (attorneys, paralegals, office managers combined). Cloud drive: Google Drive confirmed as the integration target for MVP (no multi-provider requirement stated).
- (decision) Fast-path draft written to prd.md (15 FRs across 7 features, 3 UJs, MVP scope, success metrics, non-goals). Technical/implementation detail (MCP driver mechanism, tenancy tension, bulk-import contingency) moved to addendum.md per PRD discipline (capabilities not implementation).
- (decision) Open Question #1 resolved: Docket will be multi-tenant. Data model scopes Matters/Documents/users by Firm; RBAC never crosses Firm boundaries. v1 still launches with one Firm (this firm), but firm-scoping is built in from the start, not bolted on later. New Glossary term 'Firm' and new FR-16 (firm-scoped data isolation) added.
- (decision) Assumptions confirmed as-is (user said 'agreed' to the Assumptions Index as drafted): new-doc auto-detection, once-per-crossing stale alert to Attorney+Office Manager, delegated-approval audit trail, read-only client view, warn-not-block on Filed/Sent without Reviewed, no SSO beyond Google OAuth.
