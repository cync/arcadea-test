- (decision) Paradigm: hexagonal (ports & adapters). Chosen specifically because the Drive-integration mechanism (custom API vs MCP driver) was explicitly left open by the user for architecture to decide -- a port boundary makes that choice a swappable adapter detail instead of a structural fork. [ASSUMPTION] user did not specify a paradigm.
- (decision) AD-1 Firm-scoped multi-tenancy: every domain entity carries firm_id; all data access goes through a base repository/query layer that filters by firm_id by construction, never optionally. Binds FR-16, NFR-2. Prevents a forgotten-filter cross-firm data leak.
- (decision) AD-2 Drive access via a single DriveConnector port. Binds FR-1, FR-2, FR-3. Prevents Drive-specific calls (OAuth, file listing, polling) scattering across services, which would make the custom-API-vs-MCP-driver choice structural instead of swappable. Concrete adapter choice (custom Google Drive API client vs MCP-driver-backed adapter) is Deferred to implementation -- either can implement the same port. [ASSUMPTION] resolves the user's explicit 'let architecture decide' ask by making it a non-decision at this altitude.
- (decision) AD-3 Status transitions owned by a single StatusTransition domain service (5 statuses, any-to-any per PRD's 'small firm trusts its own people' stance, warn-not-block on Filed/Sent without Reviewed). Binds FR-4, FR-5, FR-9. Prevents transition/validation logic duplicating between board UI, delegated-approval path, and API and drifting on edge cases like the Reviewed-by requirement.
- (decision) AD-4 Blocked is a computed, non-persisted derivation (true iff Status == Waiting on Client Signature) -- never a stored field. Binds FR-4, EXPERIENCE.md Blocked-badge spec. Prevents a stored Blocked flag drifting out of sync with Status.
- (decision) AD-5 Client Access enforced at the same authorization layer as staff, differentiated by role/grant, not a separate codepath or API surface -- matches EXPERIENCE.md's 'same Document Card' decision. Binds FR-11-13. Prevents a parallel client-only backend accumulating its own divergent bugs/security gaps.
- (decision) AD-6 Delegated Approval, Reviewed-by, and Attorney-of-Record reassignment are first-class immutable audit events, appended at the moment of action -- never reconstructed after the fact from mutable Document state. Binds FR-5, FR-9, FR-10, Story 1.5. Prevents an unreliable audit trail.
- (decision) AD-7 Stale-alert and any future scheduled checks run through a single scheduled-job service computing Aging the same way the live board does -- one Aging calculation, not two. Binds FR-7, FR-8, NFR-1. Prevents the emailed alert and the on-screen Aging Rail disagreeing about what's stale.
